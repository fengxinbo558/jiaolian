# 动作教练实验室

一个在浏览器里运行的单人实时健身教练原型。新版把首页、52 个徒手/瑜伽/哑铃动作、训练计划、实时训练、训练总结、历史记录和个人设置整合成一套流程。27 个已审核动作可通过电脑摄像头在本机识别人体姿态、按完整动作闭环计数或累计有效保持时间，并用短中文语音跟随当前阶段、及时打断过时提示；其余动作先开放完整教学资料，识别规则逐项审核后再启用。骨架辅助线默认关闭，识别和纠正仍会继续。

填写体重后，系统会按 `MET × 3.5 × 体重(kg) ÷ 200 × 有效运动分钟` 估算热量，并把结果联动到训练画面、结束总结、首页本周数据和历史记录。没有体重时显示“—”，不会虚构默认数据；热量只用于训练参考，不是医学或实验室测量。

- 深蹲：侧面检查深度、身体前倾和节奏；正面检查明显的膝盖内移趋势。
- 开合跳：正面检查手臂高度、双脚打开幅度、手脚同步和左右对称。
- 反向弓步：检查动作幅度、躯干稳定和前脚支撑，完成回正后计数。
- 站姿提踵：检查脚跟抬升、屈膝借力和身体晃动。
- 原地高抬腿：左右各完成一次才算一组，检查抬膝幅度和躯干稳定。
- 标准俯卧撑：侧面检查下降幅度和肩—髋—脚踝身体直线。
- 平板支撑：姿势正确才累计有效秒数，髋部偏离时暂停而不是继续虚报计时。
- 跪姿俯卧撑：检查下降幅度和肩—髋—膝身体直线。
- 登山跑：左右收膝各完成一次才计为一组，检查收膝幅度与髋部稳定。
- 平板肩触碰：左右手各触碰一次才计为一组，检查触肩幅度与髋部转动。
- 侧平板支撑：身体直线达标时才累计有效保持时间。
- 波比跳：完成站立—撑地—高位支撑—回站的闭环后计数。
- 快速动作：忙时丢弃旧帧，不积压；口令带有效期，动作进入下一阶段后旧语音会被取消而不是补播。
- 语音兜底：优先使用项目内置的离线短语音，避免浏览器虚报系统朗读能力造成静音；本地音频不可用时才尝试系统中文语音。

指导反馈分为三层：动作中用 latest-wins 短语音跟随当前阶段，过期口令会被新阶段取消；每次站直后，“上一动作”会保留本次合格情况、所有识别到的问题和下一次改法；结束训练后，“下一组重点”会根据整组问题次数给出一条可执行建议。没有完成完整动作时也会明确说明，不会误报为“暂无问题”。

## 运行

需要 Node.js 20.19 或更高版本，以及最新版 Chrome 或 Edge。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（通常是 <http://localhost:5173>）。首次打开需要联网下载 MediaPipe 的姿态模型和运行文件；随后允许浏览器访问摄像头。

生产环境使用同一个 Node 服务承载网页和 `/api/*`：

```bash
npm run build
npm start
```

服务监听平台提供的 `PORT`，默认使用 `8000`。生产环境必须配置 `SESSION_SECRET`、`INVITE_HASH_PEPPER` 和 `FORM_INVITE_HASHES`；邀请码只以 SHA-256 哈希形式保存在云端。恢复码通过服务端签名验证，不依赖实例本地文件，因此云端重启或扩缩容不会丢失访问身份。

### AI 教练

AI 教练有两层：未配置或暂时无法连接模型时，使用本机动作库与安全规则回答；配置成功后，由服务端调用 DeepSeek，并把真实模型回答标为“FORM AI 教练”。本机降级不会伪装成大模型。

1. 复制 `.env.example` 为 `.env.local`。
2. 把 `DEEPSEEK_API_KEY` 改为自己的服务端密钥；密钥不要写进网页、提交到仓库或提供给浏览器脚本。
3. 重启开发服务。AI 教练页会显示“DeepSeek 已配置；发送问题时验证连接”。只有模型真正返回结果后，该条消息才标记为 DeepSeek AI 回答。

后端使用 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 和 `DEEPSEEK_API_KEY`，支持最近 10 条对话的多轮上下文。发送模型前会按问题最小化资料：产品操作问题不发送身体或训练数据，身体趋势才会带必要的历史摘要；完整本机数据库、摄像头画面和姿态关键点都不会发送给模型。

## 第一次使用

1. 把电脑放稳，让摄像头大致位于髋部高度。
2. 先从动作库选择动作；每张卡都会显示主要肌群、辅助肌群、可用状态和已经审核的真人解剖素材。
3. 点击“开启摄像头”，模型和摄像头都就绪后点击“开始训练”。
4. 按页面提示站到起始位完成校准，然后按自己的自然节奏开始，不需要等待语音发令。
5. 点击“结束训练”查看总次数、合格次数、平均节奏、最常见问题和本组教练响应；页面会同时关闭摄像头。

语音按钮会如实显示当前状态。鼠标悬停可看到正在使用“系统语音”还是“内置本地语音”；本地音频若加载或播放失败，按钮会立即变为“语音不可用”，动作识别和画面指导仍可继续。所有语音都采用“最新动作优先”：用户进入下一阶段后，尚未播完的上一条会立即停止，不会在动作结束后补播过时指令。

建议穿与背景反差较大的衣服，并保证光线充足。当前原型一次只跟踪一个人；动作阈值是首版经验值，需要用你的真实动作继续校准。

“识别状态”显示当前核心关节点中最低的置信度。脚跟或脚尖短暂被遮挡不会再暂停动作；肩、髋、膝或脚踝短暂波动会有约 350 毫秒容错。锁定侧持续被遮挡时会自动换到可用的另一侧，短暂中断也不会计入动作节奏。只有掉点的核心关节本身贴近画面边缘时，系统才会提示后退；普通遮挡会提示调整朝向或稍微放慢动作。

## 隐私和限制

- 姿态识别在本机浏览器内完成，摄像头画面和关键点不会上传或保存。
- 身体资料、训练总结、收藏计划和教练对话保存在当前账户对应的本机加密存储中，可逐条删除，也可导出加密备份。
- 使用 DeepSeek AI 时，当前问题、最近对话及回答所需的最小资料摘要会发送给模型服务；未连接模型时由本机教练回答。
- “下蹲吸气、起身呼气”是阶段提示，不是对真实呼吸的检测；开合跳默认只提示自然呼吸和稳定落地。
- 页面显示的臀大肌、股四头肌和核心发力说明是训练知识，不是摄像头测得的真实肌肉激活或受力；这类测量通常需要肌电和力学传感器。
- 单摄像头不同视角能可靠看到的问题不同。斜侧面仍可做基础计数，但不会假装提供与正面、侧面相同的全部纠正。
- 本项目是训练辅助原型，不代替医生、康复师或专业教练的判断。

## 开源基础与动作素材

核心姿态识别使用 [Google MediaPipe](https://github.com/google-ai-edge/mediapipe) 的 Pose Landmarker，MediaPipe 代码采用 Apache-2.0 许可证。当前浏览器原型固定使用 `@mediapipe/tasks-vision@1.0.1` 和官方 Pose Landmarker Lite 模型，以降低集成成本并保证可复现。

动作目录已经完整拉取到本地只读素材库 `reference/exercises-dataset/`，参考 [hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset)。动作内容人工核对一致的图片或 GIF 直接进入页面，并保留 `© Gym visual` 来源标记；用户已授权本项目使用这些媒体，但不将第三方媒体错误标成 MIT。素材库没有完全匹配动作时，使用项目自有的“黑白线稿人体、黑色短裤、红色发力肌群、白底”补充图，并在页面上明确区分来源。人工复核发现开合跳目录编号 `3224` 的文字说明与关联媒体内容错配，因此开合跳不使用该媒体，继续采用项目内已核对的三阶段示范。
