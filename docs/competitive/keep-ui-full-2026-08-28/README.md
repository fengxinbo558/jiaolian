# Keep 全功能界面截图册与结构分析

更新时间：2026-08-28

这份截图册不是只挑“好看的首页”。它按完整用户流程收集 Keep 的公开界面证据：发现内容、选择计划、训练前、训练中、训练后、跑步、AI 教练、饮食、身体数据、社区、赛事、设备、会员、商城和个人中心。

## 先说明版本边界

- **现行官方界面**：App Store 的 Keep 9.1 系列官方截图，最适合判断当前产品主叙事与一级能力。
- **Keep 9.0 实际界面**：2026 年公开评测中的实机截图，适合分析现行信息架构、AI 教练、计划和数据闭环。
- **历史深层流程**：公开资料中的较早版本截图。它们不代表 2026 年视觉，但能补齐训练中、暂停、完成、社区发布、饮食录入、设备绑定等现行商店截图没有公开展示的深层页面。
- **无法公开验证的页面**：登录/注册、支付收银台、部分会员实验页、特定硬件固件页和灰度测试页面。没有登录 Keep 真机账户，不能把这些说成“当前完整实机截图”。

## 结构分析：Keep 真正做的是五层闭环

### 1. 发现层

首页、课程、活动、社区和商城负责把用户带到一个具体目标。它们不是训练本身，而是降低“今天练什么”的决策成本。

### 2. 计划层

AI 问卷、固定计划、日历、休息日和请假，把一次训练变成连续周期。计划能被调整，而不是生成后就不管。

### 3. 执行层

课程详情负责预期管理；动作页负责示范；训练中页面只保留计时、动作、暂停和退出；结束页马上给出客观结果与下一步。

### 4. 数据层

运动、体重、饮食、健康状态、周报和能力评估被组织成趋势，而不是孤立数字。用户能看到“这周发生了什么”和“下一步怎么改”。

### 5. 留存层

等级、徽章、赛事、社区、会员和设备连接，把训练行为变成长期身份、社交关系和资产积累。

## 对我们产品最值得借鉴的部分

1. **实时纠正不是独立功能**：它必须嵌在“选动作—看示范—开始训练—实时反馈—结束复盘—进入下次计划”的完整链路里。
2. **训练中要比首页更克制**：示范动作、用户摄像头、当前阶段、次数、最重要的一条纠正和暂停按钮必须同屏，不能让用户滚动找示范。
3. **AI 应该出现在需要判断的地方**：计划生成、语音理解、照片识别、姿态判断、训练后总结；普通导航、计时、公式计算不需要大模型。
4. **结束页不能默认夸奖**：应先判断有效训练时长、完成次数、动作质量和中断原因，再给事实、优先问题和下一次目标。
5. **视觉层和动作教学层要分开**：真人视觉用于首页、计划封面和课程封面；统一的动作模型用于动作拆解和纠正，避免封面动作与训练动作不一致。

## 暂时无法证明为“现行 9.1 实机”的页面

- 登录、注册、验证码和隐私授权完整流程
- iOS/Android 当前支付收银台
- 不同会员人群的灰度实验页
- 每一种 Keep 硬件的配对、固件升级和异常恢复页
- 社区举报、私信、群组和全部创作者工具
- 所有设置二级页和系统权限页

这些页面不是不存在，而是公开资料无法可靠确认其 2026 年现行样式。要做到真正的“每一页现行截图”，下一步必须在登录后的 Keep 真机中逐页走查。
