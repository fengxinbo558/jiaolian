# 身体状态与运动能力中心：第一阶段实施计划

> 对应已确认设计：`docs/superpowers/specs/2026-08-21-ai-body-nutrition-coach-design.md`

## 目标

在不改动现有动作识别、语音纠正和训练记录主流程的前提下，把原“设置”页增量升级为“身体”页，让用户能够：

1. 保存年龄、公式性别、身高、体重、活动水平和可选围度；
2. 查看 BMI、健康体重参考范围、BMR、TDEE、腰高比、腰臀比和可选体脂估算；
3. 看到本机保存的身体变化记录与上次变化；
4. 记录器械动作重量/次数/RIR/动作质量，以及徒手动作次数或保持时长；
5. 获得透明、可解释的 e1RM 与下一次负重建议；
6. 自动迁移原设置页已有体重，并继续供训练热量估算使用。

## 实施边界

- 本阶段不接入云端大模型、照片识别、食品数据库或医疗结论。
- 所有数据只保存在当前浏览器；界面明确显示“估算/参考”。
- 采用新增独立模块和版本化存储键，避免整体重写 `main.ts`。
- 保留原 `move-local:settings:v1`，体重在新档案与旧偏好间做兼容同步。

## 任务清单

### 1. 身体公式与验证

- 新建 `src/body/metrics.ts`。
- 实现 BMI、健康体重范围、Mifflin-St Jeor BMR、活动系数 TDEE、腰高比、腰臀比、美国海军体脂估算、脂肪量、去脂体重和 FFMI。
- 缺少必要数据或输入非法时返回空值，不编造结果。
- 新建 `src/body/metrics.test.ts` 覆盖正常值、边界值和缺失值。

### 2. 身体档案与趋势存储

- 新建 `src/body/profile.ts`。
- 使用 `form:body-profile:v1` 和 `form:body-snapshots:v1`。
- 首次加载时读取旧偏好体重作为迁移值。
- 保存时规范化数据，同一天重复保存更新当天记录，避免重复噪声。
- 新建 `src/body/profile.test.ts` 覆盖迁移、非法数据、保存和同日合并。

### 3. 运动能力记录

- 新建 `src/capacity.ts`。
- 使用 `form:capacity-records:v1` 保存器械和徒手记录。
- 器械记录必须说明重量口径；2–10 次时用 Epley 公式估算 e1RM。
- 下一次负重建议只根据最近两次 RIR 与动作质量给出“增加/保持/降低”，并显示依据。
- 徒手记录支持次数和静态保持时长。
- 新建 `src/capacity.test.ts` 覆盖 e1RM、建议策略、存储容错。

### 4. “身体”页面与交互

- 将底部导航“设置”改为“身体”，更新 `AppView`。
- 在 `index.html` 建立四个连续区块：状态概览、身体档案、运动能力、隐私与显示设置。
- 新建 `src/ui/body-center.ts`，负责表单、指标渲染、趋势、能力记录和无数据状态。
- `main.ts` 只负责初始化、体重同步回调与原骨架开关，避免继续膨胀。
- 所有输入具备标签、说明、错误提示、键盘操作和清晰焦点状态。

### 5. 视觉设计

- 延续当前暖色纸张、深墨色和珊瑚强调色，不引入第二套设计语言。
- 用大数字指标卡、轻量趋势条和清晰的能力记录卡代替廉价仪表盘或火柴人。
- 桌面端采用非对称两栏，移动端单列；不横向溢出。
- 用字体、留白和色彩表达层级，避免过多边框与装饰。

### 6. 集成与验收

- 原训练热量继续读取同步后的体重。
- 运行所有单元测试和生产构建。
- 启动本地网页，用浏览器验证：导航、旧体重迁移、档案保存、公式刷新、能力记录、空状态、移动端布局、控制台错误。
- 截图进行视觉自检；发现布局或可读性问题后修正并重测。

## 完成标准

- 老用户原体重无需重复填写；新用户不会看到虚构指标。
- 公式结果旁能看见“估算/参考”与计算条件。
- 器械重量口径明确，e1RM 仅在适用范围出现。
- 用户能在一分钟内完成一次身体档案和一次运动能力记录。
- 现有动作库、实时训练、计划、记录、语音和热量功能无回归。
- 单元测试、生产构建和真实网页流程均通过。
