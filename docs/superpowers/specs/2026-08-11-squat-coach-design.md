# 电脑摄像头深蹲教练：最小原型设计

## 目标

构建一个供个人使用的浏览器原型。用户站在电脑摄像头侧面，系统在本机实时识别单人深蹲，叠加人体骨架，统计次数，并通过中文画面与语音提示深度、躯干前倾、动作节奏和呼吸节奏。

## 本期范围

- 电脑浏览器与单个摄像头。
- 单人、徒手、侧面深蹲。
- 站立校准、动作阶段识别、总次数和合格次数。
- 深度不足、躯干明显前倾、下蹲过快提示。
- 下蹲吸气、起身呼气的节奏提示；不宣称检测真实呼吸。
- 训练总结包含总次数、合格次数、主要问题和平均节奏。
- 训练摘要仅保存在当前浏览器；视频帧和人体关键点不上传、不持久化。

## 不在本期范围

- 正面视角的膝盖内扣判断。
- 多人跟踪、账号、云同步、排行榜和服务端分析。
- 医疗诊断、康复建议或替代专业教练。
- 自训练姿态模型。

## 技术设计

浏览器摄像头把抽样视频帧传给 Web Worker。Worker 使用 MediaPipe Pose Landmarker 在端侧产生最多一人的 33 个关键点，并将标准化结果和画面宽高比交给主线程。分析前先用宽高比还原正确的几何比例，避免 16:9 画面扭曲关节角度。独立的 TypeScript 分析核心完成关键点平滑、逐点可见性检查、侧面选择、站立校准、深蹲状态机和纠错规则。界面与语音模块消费统一的分析结果，不直接依赖 MediaPipe。

内部姿态数据从第一版开始使用人物数组，分析器只选择主要人物。后续多人版本可在分析器前加入稳定的人物跟踪和编号；手机版本可替换摄像头与姿态提供器，继续复用深蹲分析核心。

## 动作与反馈规则

一次动作经过站立、下蹲、最低点、起身、再次站立的完整周期才计数。状态切换采用角度迟滞和连续帧确认，避免阈值附近抖动导致重复计数。到达站立后，系统根据最低深度、最大躯干倾角和下降用时判断是否合格。

反馈一次只播报一条。优先级为画面/关键点不可用、姿势问题、动作速度、呼吸节奏；同类语音设置冷却时间。姿势条件必须连续存在一段时间才触发，不根据单帧结果提醒。

### 关键点稳定性与误提示修正

- 深蹲阶段和角度分析只把肩、髋、膝、脚踝作为必需关节点；脚跟和脚尖用于骨架显示及后续足部规则，但单独掉点不能阻断计数。
- 必需关节点的最低可见度门槛为 `0.45`。短于 `350ms` 的识别波动继续保持当前动作状态，不暂停、不清空本次动作；持续超过容错时间后才进入暂停。
- 有效关键点恢复时，“识别不稳定”提示立即让位于当前动作提示，不继续滞留。
- 只有在已检测到人体、且掉点的那个核心关节点本身贴近画面边缘时才提示“请后退”；其他清晰关节点或脚尖单独贴边不能替掉点关节提供出框证据。遮挡或运动模糊统一提示“关键点暂时不稳定，请保持侧身并放慢动作”。完全没有检测到人体时提示“没有稳定识别到人体”。
- 校准期间用核心关节点选择更清晰的一侧。校准完成后优先保持侧别稳定；当前侧持续不可靠 `350ms`、而另一侧达到分析门槛时才切换，并清除旧侧的平滑历史、角速度与站立锁定计时，避免切侧制造假动作。
- 明确的短暂跟踪中断不计入动作节奏、下降用时、前倾持续时间或站立锁定时间，恢复后必须重新积累连续稳定时间。连续有效但帧率较低时仍按真实墙钟计时，避免低性能设备不计数。
- 动作读数中显示简短识别状态和当前核心关节点最低置信度，便于现场区分出框、遮挡和短暂波动。

## 用户流程

1. 用户开启摄像头并允许浏览器访问。
2. 系统提示用户侧身、后退到全身入镜。
3. 用户开始训练，站直约两秒完成校准。
4. 页面持续显示镜像摄像头、骨架、阶段、计数和主要提示。
5. 用户结束训练后摄像头自动关闭，并看到本次总结和保存在本机的最近记录。

## 异常处理

- 浏览器不支持或拒绝摄像头时，显示具体原因和解决方向。
- 模型下载或初始化失败时，允许重试，不启动训练。
- 人体不完整或任一必需关节点持续不可见超过容错时间时，暂停动作计数。首版只分析一个主要人物，多人入镜不保证结果可靠。
- 页面隐藏、摄像头中断或模型长时间无结果时，暂停训练并保留已完成统计。
- 浏览器不支持语音时仍保留全部画面提示。

## 验证

- 使用合成关键点序列测试完整深蹲、浅蹲、过快动作、前倾和关键点丢失。
- 回归测试覆盖：脚跟或脚尖低置信度仍可分析；单帧核心关节点掉点不暂停；持续掉点才暂停；低置信度与贴边使用不同提示；有效帧恢复后立即清除跟踪提示；动作中安全换侧；跟踪暂停不污染锁定和节奏计时；长期丢失后重新校准。
- 运行类型检查、生产构建和单元测试。
- 在本地浏览器验证首屏、摄像头授权、开始/结束训练、错误提示、键盘焦点、响应式布局和本地总结。
- 人工测试时用侧面正确深蹲与典型错误各完成若干次，再按实际表现调整配置阈值。
