# 开合跳人体示范、实时语音与响应状态设计

**日期：** 2026-08-19  
**状态：** 用户已确认方案 1，进入实施

## 目标

让用户在不盯着屏幕的情况下，也能按自然速度完成开合跳并及时获得指导；页面使用清晰的人体动作示范，不再使用错误素材或难以理解的火柴人；技术延迟转换为用户能理解的教练响应状态。

## 人体动作示范

- 继续使用素材库 ID `3224` 的名称、中文步骤、肌群和阶段元数据。
- 不使用该记录错配的 GIF。
- 依据文字标准制作一张无文字的人体三阶段示范：并拢站立、手脚同时张开且双手过头、重新并拢。
- 示范必须为正面全身、运动服、清晰关节轮廓；不得出现火柴人、屈体跳、深蹲或手臂只到水平位置。
- 页面显示来源说明：“动作标准依据 exercises-dataset ID 3224 文字步骤，媒体经人工复核后重新制作”。

## 实时语音

- 用户点击“开始训练”时立即播报“开始训练”，既确认声音可用，也满足浏览器对用户手势启动语音的要求。
- 开合跳阶段只使用短口令：“张开”“收回”。
- 动作完成使用短评价；开始下一次动作时立即取消上一条评价，不排队补播。
- 延长完成评价的有效窗口，但阶段口令仍保持短有效期；过期内容直接丢弃。
- 保留当前发声对象，避免浏览器提前回收；语音关闭后立即停止，重新开启时播报“语音已开启”。

## 教练响应

- 训练中不再显示难懂的 `P95` 技术字符串，改为：`流畅 / 正常 / 偏慢`，并同时显示当前毫秒数。
- 页面解释该数值是“从摄像头画面进入系统，到完成动作判断所需时间，越低越跟手”。
- 每组训练独立统计平均响应和 P95 响应。
- 训练总结新增“教练响应”项目，例如“流畅 · P95 142 毫秒”；没有数据时显示“未测得”。
- 历史记录继续保持简洁，不增加延迟明细。

## 验收

1. 开始训练或重新开启语音后能立即听见确认音。
2. 0.5–0.6 秒开合跳事件顺序为“张开 → 收回 → 完成”，下一次张开能中断旧评价。
3. 人体示范明确展示标准三阶段，不使用素材库错误 GIF或火柴人。
4. 实时读数有自然语言解释，结束总结包含本组响应状态。
5. 自动测试、类型检查、生产构建和桌面/手机页面回归通过。
