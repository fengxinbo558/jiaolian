# 徒手动作库扩展设计

**日期：** 2026-08-20  
**状态：** 用户已确认产品方向，等待规格复核后实施  
**范围：** 在现有徒手深蹲、开合跳基础上新增 15 个徒手动作，总计 17 个动作

## 1. 目标

新增动作不能只出现在菜单中。每个正式可训练动作必须具备：

- 明确的起始姿势、推荐拍摄视角和入镜范围。
- 可验证的动作阶段、完整闭环计数或有效保持时间。
- 实时短语音纠正，阶段变化后停止过期语音。
- 单次动作评价和整组训练总结。
- 主要训练肌群、辅助参与肌群和一条发力说明。
- 标准动作、常见错误、快速动作、遮挡、不同帧率和恢复场景测试。
- 经过人工核对的真人或解剖动作素材；未通过审核的动作不开放训练。

普通摄像头只能判断可见动作，不能测量真实肌肉激活、关节压力或落地冲击力。页面必须明确区分“训练知识”和“摄像头检测结果”。

## 2. 动作范围与批次

### 第一批

1. 反向弓步
2. 提踵
3. 高抬腿
4. 标准俯卧撑
5. 平板支撑

### 第二批

6. 侧弓步
7. 臀桥
8. 跪姿俯卧撑
9. 鸟狗式
10. 登山跑

### 第三批

11. 徒手单腿硬拉
12. 平板肩触碰
13. 侧平板支撑
14. 死虫式
15. 波比跳

三批共享底层框架，但逐批完成规则、语音、测试和真人页面验收。后一批不能以牺牲前一批稳定性为代价并行堆入正式训练入口。

## 3. 动作类型

动作分析协议支持三种计量方式：

- `repetition`：完整往返闭环计一次，例如俯卧撑和提踵。
- `alternating`：左右两侧完成后形成一个完整循环，例如鸟狗式和肩触碰；界面同时显示侧次和完整循环。
- `timed-hold`：只累计姿势合格的有效保持时间，例如平板和侧平板；姿势失效或跟踪中断时暂停累计。

波比跳等复合动作必须按顺序经过全部关键阶段，缺少中间阶段不能在回到站立后补算。

## 4. 肌肉信息模型

每个动作资料增加以下结构化字段：

```ts
interface MuscleProfile {
  primaryMuscles: string[];
  secondaryMuscles: string[];
  activationCue: string;
  trainingNote: string;
  sourceType: "catalog" | "reviewed-reference";
}
```

- `primaryMuscles`：动作主要负荷目标。
- `secondaryMuscles`：协同发力或稳定身体的肌群。
- `activationCue`：用户能执行的一句话发力提示。
- `trainingNote`：说明摄像头可见动作与真实肌肉发力之间的边界。
- `sourceType`：标明信息来自素材目录还是人工复核资料。

展示位置：

1. 动作库卡片显示主要训练部位。
2. 动作详情显示主要肌群、辅助肌群和发力提示。
3. 训练中只在准备阶段展示肌群知识，不占用实时纠正位置。
4. 训练总结说明本组主要训练部位，但不声称测得实际肌肉受力。

正式界面不使用抽象火柴式人体图。优先采用经人工核对的 `exercises-dataset` 真人解剖动作素材；没有匹配素材时使用清楚的文字，不制作难以辨认的替代图。

## 5. 素材库落盘与审核

公开仓库 `hasaneyldrm/exercises-dataset` 完整保存到项目的只读参考目录：

`reference/exercises-dataset/`

运行时不直接遍历第三方仓库，而是读取项目生成的审核清单：

```ts
interface ReviewedExerciseAsset {
  exerciseId: string;
  catalogId: string;
  sourcePath: string;
  mediaPath: string | null;
  actionNameMatches: boolean;
  phasesMatch: boolean;
  musclesMatch: boolean;
  reviewStatus: "approved" | "rejected";
  rejectionReason?: string;
}
```

审核顺序固定为：动作名称、媒体实际内容、动作阶段、主要肌群、辅助肌群、左右方向和清晰度。任一关键项不一致即拒绝使用。编号 `3224` 的既有错配继续保留为回归案例，防止“有编号就直接采用”。

项目保留原始来源、许可证和署名。用户已明确允许当前项目使用素材，但仍保留来源信息和审核记录，方便后续发布时复核具体媒体权利。

## 6. 分析架构

共用层负责：

- 核心关节点可见性与画面裁切判断。
- 校准、遮挡宽限、恢复和低帧率处理。
- 视角确认、左右侧选择和时间戳规范化。
- 动作结果、教练事件和训练总结的统一输出。

动作专属层负责：

- 所需关键点与支持视角。
- 起始位、阶段转移和完成闭环。
- 基于个人校准的幅度和姿势规则。
- 主要问题优先级、短语音和总结建议。

不能用同一组固定角度阈值套用全部动作。单侧动作必须保存左右基线；地面动作必须重新校准身体尺度和摄像头视角。

## 7. 动作规则与语音

| 动作 | 完成条件 | 首要纠正 |
|---|---|---|
| 反向弓步 | 后撤、下沉、起身、并脚 | 前膝方向、躯干稳定、下沉幅度 |
| 侧弓步 | 侧跨、屈髋、推回 | 髋部后移、膝盖方向、非支撑腿伸展 |
| 臀桥 | 抬髋、顶峰、控制落下 | 髋部高度、腰部反弓、下降控制 |
| 提踵 | 抬跟、顶峰、脚跟落地 | 抬升幅度、膝盖弯曲、身体晃动 |
| 单腿硬拉 | 单脚稳定、髋折叠、回正 | 背部稳定、髋部后移、支撑膝轨迹 |
| 标准俯卧撑 | 高位、下降、底部、推起 | 身体直线、下降深度、髋部塌落 |
| 跪姿俯卧撑 | 跪姿高位、下降、推起 | 肩髋膝直线、下降深度、腰部稳定 |
| 平板肩触碰 | 触肩、回位、换侧 | 髋部旋转、手掌位置、左右交替 |
| 平板支撑 | 合格姿势连续保持 | 髋部过低、臀部过高、肩肘位置 |
| 侧平板 | 合格侧撑连续保持 | 髋部高度、身体直线、躯干旋转 |
| 鸟狗式 | 对侧伸展、回位、换侧 | 对侧配合、骨盆水平、伸展幅度 |
| 死虫式 | 对侧伸展、回位、换侧 | 腰背稳定、对侧同步、动作控制 |
| 高抬腿 | 左右交替形成循环 | 抬膝高度、躯干后仰、左右节奏 |
| 登山跑 | 平板下左右交替提膝 | 髋部稳定、提膝幅度、肩腕位置 |
| 波比跳 | 下撑、后跳、回收、站起 | 支撑稳定、阶段完整、站直锁定 |

训练中语音只使用当前仍可执行的短口令，例如“抬髋”“膝盖对准脚尖”“身体成一直线”。每次动作最多播报一个最重要的问题；其余问题只进入上一动作卡和总结。快速动作的单次结果语音如果已经进入下一次动作则自动丢弃。

## 8. 用户流程

1. 动作库按下肢、上肢、核心和全身有氧分组。
2. 选择动作后先查看真人动作素材、拍摄方向、肌群和安全要点。
3. 开启摄像头后按该动作要求完成起始位校准。
4. 用户按自然节奏运动，不等待语音发令。
5. 训练中画面显示当前阶段，语音只播短纠正。
6. 单次完成后更新持久评价卡。
7. 结束训练后显示次数或有效时长、合格情况、主要训练部位、最常见问题和下一组重点。

## 9. 错误与安全边界

- 无法检测到人体时不判断动作错误。
- 所需关节点短暂丢失时冻结阶段；持续丢失后取消当前未完成动作。
- 不支持的拍摄方向只给视角提示，不套用错误规则。
- 动作素材未审核、规则未完成或测试未通过时显示“开发中”，开始训练按钮不可用。
- 俯卧撑、平板和波比跳训练前提示清理地面空间；出现明显跟踪跳变时暂停，不用错误坐标生成安全建议。

## 10. 测试与质量门槛

每个动作至少覆盖：

- 标准动作。
- 幅度不足。
- 各项支持的典型姿势问题。
- 半程动作和错误阶段顺序。
- 自然速度、快速动作和短暂停顿。
- 15、30、60 FPS 等价轨迹。
- 低性能设备的稀疏结果间隔。
- 单点低置信度、短暂遮挡和持续遮挡。
- 恢复后不得补算中断动作。
- 左右侧切换与交替动作完整性。
- 新阶段语音打断旧阶段语音。

动作进入正式入口的门槛：单元测试、类型检查、生产构建、桌面和手机布局检查、素材匹配审核、模拟轨迹回归和真实摄像头验收全部通过。

## 11. 实施顺序

1. 保存并索引本地素材库，建立审核清单。
2. 扩展动作、肌群、媒体和分析器数据协议。
3. 改造动作库和动作详情界面。
4. 建立三类共享分析框架。
5. 按第一、第二、第三批逐个实现和验收。
6. 完成 17 个动作的全量回归，并保留未通过动作的禁用状态。

## 12. 明确不做

- 不用素材图片逐像素比对用户姿势。
- 不把目录里的肌群标签直接当作摄像头测量结果。
- 不因赶数量降低动作闭环、语音时效或遮挡保护标准。
- 不在未审核时展示错误动作图片。
