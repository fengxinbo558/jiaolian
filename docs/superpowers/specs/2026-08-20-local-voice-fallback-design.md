# 本地语音兜底设计

**日期：** 2026-08-20  
**状态：** 已实施并验证

## 问题

当前内置浏览器没有提供 `SpeechSynthesis` 系统语音接口。页面仍允许显示“语音开启”，但所有播报都会静默失败，用户无法知道语音实际不可用。

## 方案

- 为训练核心口令提供项目内置的本地中文音频文件。
- 优先使用可控的本地音频，避免部分浏览器暴露系统语音接口却实际静音。
- 本地音频不可用时才尝试系统语音；两种方式都不可用时明确显示不可用。
- 本地语音与系统语音共用“最新动作优先”规则：新阶段立即停止旧音频，不排队补播过时内容。

## 本地语音范围

首版至少包含：

- 状态：开始训练、语音已开启、可以开始、识别不稳。
- 深蹲：下蹲、起身、抬胸、膝盖朝向脚尖、动作合格、动作完成。
- 开合跳：张开、收回、手举高、脚打开、手脚同步、两侧同高、动作合格、动作完成。

系统语音不可用时，动态“第 N 次”简化为“动作合格”或具体纠正；次数继续在画面准确显示。

## 播放规则

- 用户点击“开始训练”时立即解锁并播放“开始训练”。
- 用户重新开启语音时立即播放“语音已开启”。
- 每次只保留一个正在播放的音频；新动作到来时停止并归零上一条。
- 过期事件不播放，短时间重复事件遵守现有冷却规则。
- 音频加载或播放失败时，页面显示“语音暂不可用”，不能继续显示虚假的开启状态。

## 隐私与性能

- 音频作为静态资源随项目提供，不上传画面、动作数据或播报文本。
- 核心口令使用短音频，避免联网等待和长语音挡住下一动作。
- 本地音频加载失败不影响识别、计数和画面反馈。

## 验收

1. 在没有 `SpeechSynthesis` 的当前内置浏览器中，点击开启或开始训练能听到本地确认音。
2. 深蹲自然速度下依次播放下蹲、起身、结果；开合跳依次播放张开、收回、结果。
3. 用户进入下一阶段时，上一条未播完的音频立即停止。
4. 语音关闭后没有任何播报；重新开启后立即听到确认音。
5. 本地音频无法播放时，按钮和提示明确显示不可用。
6. 自动测试、类型检查、生产构建和真实页面回归通过。
