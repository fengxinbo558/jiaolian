# FORM 150 动作库、统一动图与个性化训练计划设计

日期：2026-08-24  
状态：待用户书面确认  
适用项目：`fitness-coach`

## 1. 目标

在不整体重写现有 TypeScript 网页应用的前提下，将动作库从 52 个扩展到约 152 个，并增加 12 套固定训练、个性化推荐、本地自定义计划生成、收藏与再次训练能力。

本次扩展必须同时保证：

- 动作资料正确，不通过重复或改名凑数量；
- 所有新增可见素材使用同一个人物、服装、画风和背景；
- 能可靠通过单摄像头判断的动作才开放实时纠正；
- 不能可靠判断的动作仍提供完整跟练指导，但不冒充实时教练；
- 固定计划和个性化推荐有可解释的规则，不根据身高体重随意贴强度标签；
- 当前没有大模型 API 时仍可工作，后续可无痛接入模型；
- 每批次都能单独测试、回退和继续，不破坏现有训练体验。

## 2. 已有基础与边界

当前应用已有：

- 52 个动作资料；
- 8 套可运行的单次训练计划；
- 本地 MediaPipe 姿态识别；
- 深蹲、开合跳和一批徒手、瑜伽、哑铃动作的实时分析器；
- 身高、体重、年龄、活动水平和围度记录；
- 器械重量、次数、组数、RIR 与动作质量记录；
- 语音输入、语音指导、训练记录和热量估算。

本阶段不提供：

- 医疗诊断、疾病治疗、用药或康复处方；
- 对疼痛或疾病原因作判断；
- 在浏览器前端保存大模型 API Key；
- 对摄像头看不清的关节或被器械遮挡的动作作虚假实时纠正；
- 未经逐项审核的 AI 连续视频。

## 3. 总体实施策略

采用“分批生产、逐项审核、持续完成”的方式，每批 20–25 个动作。每批依次完成：

1. 动作定义和去重；
2. 肌群、呼吸、轨迹、错误和安全资料；
3. 实时识别可行性分级；
4. 3–5 个统一人物关键帧；
5. 关键帧逐项视觉审核；
6. 生成循环动画；
7. 数据、素材和识别测试；
8. 网页桌面与手机宽度检查。

单个动作失败时标为 `media-review-failed` 或 `realtime-review-failed`，继续处理同批其他动作。失败动作不能显示为“已审核”或“支持实时纠正”。

## 4. 动作分级

### 4.1 A 级：实时教练

只有同时满足以下条件才设为 `available: true`：

- 单人、单摄像头能看到主要关节；
- 至少存在一个明确推荐视角；
- 起始、发力、顶点或底部、还原阶段可由关键点稳定区分；
- 计数或计时有可测试的状态机；
- 至少能检测一个动作幅度问题和一个稳定或对齐问题；
- 快速动作不会因为语音队列造成过时提醒；
- 正面、侧面或斜侧面的支持范围写清楚；
- 模拟关键点测试和真实摄像头检查均通过。

### 4.2 B 级：跟练指导

适用于关节遮挡明显、需要长凳或锚点、器械容易挡住关键点，或动作轨迹无法由 2D 单摄像头可靠判断的动作。必须包含：

- 统一循环动图；
- 主要和辅助肌群；
- 起始姿势；
- 3–5 个动作阶段；
- 呼吸提示；
- 常见错误和改法；
- 安全提示；
- 建议次数、时间、组数和休息；
- 推荐拍摄或观看角度。

界面明确显示“跟练指导”，不出现“实时纠正”按钮。

## 6. 统一人物与动图规范

### 6.1 角色圣经

建立唯一的角色参考文件，后续所有图片生成或编辑都必须引用：

- 成年男性中性健身解剖线稿，不追求真人皮肤质感；
- 无明显表情，五官克制但头部完整；
- 黑色短发；
- 黑白灰肌肉线稿；
- 黑色、无图案、覆盖充分的运动短裤；
- 不出现裸露感、透明衣物或身体私密部位轮廓；
- 肢体长度和肌肉比例固定；
- 主要肌群为统一珊瑚红，辅助肌群不使用另一种高饱和色；
- 背景为统一米白；
- 器械统一为深灰或黑色，不使用品牌标识。

### 6.2 关键帧

每个动作使用 3–5 帧：

- 起始；
- 第一移动阶段；
- 顶点或最低点；
- 返回阶段；
- 必要时增加左右侧或中间过渡。

循环顺序一般为 `1-2-3-4-3-2`，避免从结束帧瞬间跳回起始帧。静态拉伸可使用轻微呼吸循环，但不能让关节漂移。

### 6.3 视觉审核

每帧必须检查：

- 人物是否为唯一角色；
- 头、手、脚是否完整入画；
- 手指数、四肢数是否正确；
- 关节弯曲方向是否符合人体结构；
- 左右腿和手臂是否错误交叉；
- 短裤是否完整遮挡；
- 哑铃、弹力带、长凳是否穿过身体；
- 弹力带锚点和受力方向是否合理；
- 动作是否与名称一致；
- 红色肌群是否与主要训练部位一致；
- 相邻帧人物比例、头型、服装和器械是否一致；
- 动图播放是否能看懂轨迹且没有闪烁。

审核结果写入素材清单。只有 `visualReview: verified` 才能在正式动作库显示。

## 7. 12 套固定训练计划

现有 8 套计划保留，但重新纳入统一的计划元数据。新增的 12 套固定计划为完整单次训练；推荐系统再将单次训练组合为一周安排。

### 7.1 轻强度（4 套）

1. **轻松有氧入门**：低冲击侧步开合、半蹲侧向行走、站姿交替提膝下压、低幅度徒手深蹲；15–20 分钟。
2. **新手全身力量**：靠墙俯卧撑、徒手深蹲、臀桥、鸟狗式、提踵；20–25 分钟。
3. **活动度与舒展**：猫牛式、低位弓步、半神猴式、开书式、婴儿式；18–22 分钟。
4. **核心与平衡基础**：死虫式、鸟狗式、熊爬静态支撑、树式、侧平板简化；18–22 分钟。

### 7.2 中等强度（4 套）

1. **中等有氧循环**：开合跳、后踢腿跑、高抬腿、登山跑、低冲击恢复段；20–25 分钟。
2. **哑铃全身力量**：前架深蹲、罗马尼亚硬拉、地板卧推、俯身划船、肩推；30–40 分钟。
3. **臀腿力量与稳定**：反向弓步、哥萨克深蹲、单腿臀桥、弹力带侧向走、提踵；28–35 分钟。
4. **上肢推拉与核心**：俯卧撑、弹力带划船、肩推、弯举、平板上下转换；28–35 分钟。

### 7.3 高强度（4 套）

1. **高强度心肺间歇**：波比跳、开合跳、高抬腿、登山跑、跳跃深蹲；18–24 分钟。
2. **哑铃力量强化**：双哑铃前架深蹲、传统硬拉、卧推、胸托划船、Z 推举；40–50 分钟。
3. **徒手进阶力量**：下斜俯卧撑、保加利亚分腿蹲、印度俯卧撑、单腿臀桥、V 字卷腹；35–45 分钟。
4. **混合力量与心肺**：哑铃深蹲推举、俯卧撑划船、哑铃行走弓步、平板开合跳、负重原地行进；30–40 分钟。

### 7.4 每套计划的必填字段

- 目标；
- 强度；
- 适用训练经验；
- 预计时长；
- 需要器械；
- 热身；
- 动作顺序；
- 每个动作的组数、次数或秒数；
- 组间休息；
- 动作间休息；
- 冷身；
- 每周建议频率；
- 主要肌群覆盖；
- 高冲击标记；
- 推荐理由模板；
- 不适用条件和替代动作。

## 8. 科学编排依据

计划以普通健康成人的一般健身建议为范围：

- WHO：成年人每周至少进行 150 分钟中等强度或 75 分钟高强度有氧活动，并至少 2 天训练主要肌群；更多活动可带来额外收益。
- ACSM 2026：规律参与和覆盖主要肌群比复杂技巧更重要；目标、训练量、安全和可坚持性应个体化；徒手、弹力带和家庭训练同样有效。

产品内必须显示“本工具提供一般健身建议，不能替代专业教练或医疗建议”。用户报告疼痛、眩晕、胸闷或明显不适时，不生成高强度计划，只提示停止训练并寻求合适的专业帮助，不分析疾病原因。

参考来源：

- WHO Physical Activity: https://www.who.int/initiatives/behealthy/physical-activity
- ACSM 2026 Resistance Training Guidelines: https://acsm.org/resistance-training-guidelines-update-2026/

## 9. 个性化推荐

### 9.1 输入

复用已有数据并补充用户偏好：

- 年龄；
- 身高、体重和围度；
- 活动水平；
- 训练目标；
- 训练经验；
- 每周可训练天数；
- 单次可用时间；
- 可用器械；
- 喜欢和排除的动作；
- 是否接受跳跃和地面动作；
- 最近训练完成率；
- 最近动作合格率；
- 器械工作重量、次数、组数、RIR 和动作质量；
- 徒手最大次数或保持时间；
- 最近同肌群训练时间。

身高、体重、BMI 或体脂估算不能单独决定训练强度。它们主要用于热量估算、冲击提示和动作空间建议。训练强度主要由经验、近期完成情况、动作质量、RIR、可用时间和用户选择共同决定。

### 9.2 推荐流程

1. **完整性检查**：确认目标、器械、时间和训练经验；缺失项使用保守默认值并告诉用户。
2. **动作过滤**：移除用户排除动作、不可用器械、超出时间、冲击偏好不符和未审核动作。
3. **强度上限**：新手、近期无训练记录或动作质量偏低时不推荐高强度。
4. **计划评分**：按目标匹配、器械匹配、时长匹配、历史完成率、肌群恢复和动作熟悉度评分。
5. **理由生成**：输出 2–3 条基于真实数据的理由，不使用空泛夸奖。
6. **替代动作**：每个计划至少提供一个低冲击或无器械替代。
7. **周安排**：避免连续两天安排同一主要肌群高负荷；高强度训练之间保留恢复日或轻训练。

### 9.3 输出

- 首选计划；
- 两个备选计划；
- 推荐理由；
- 本周建议训练天数；
- 建议周安排；
- 为什么没有推荐更高或更低强度；
- 根据最近表现调整后的次数、秒数、重量或休息；
- 数据不足提示。

## 10. 自定义计划与模型接口

### 10.1 当前离线方案

用户可输入或语音说出，例如：“我今天只有 25 分钟，有一对 5 公斤哑铃，不想跳，想练臀腿和核心。”

本地解析器提取：

- 时长；
- 目标；
- 强度；
- 器械；
- 训练部位；
- 排除动作；
- 是否跳跃；
- 训练形式偏好。

规则生成器从已审核动作中选择热身、主要复合动作、辅助动作、核心或心肺结束段和冷身，随后由同一验证器检查训练量、重复肌群、器械和时长。

### 10.2 后续模型方案

预留：

```ts
interface PlanModelProvider {
  generate(request: PlanGenerationRequest): Promise<PlanGenerationDraft>;
}
```

浏览器只调用项目自己的服务端 `/api/plan/generate`。API Key 只保存在服务端环境变量中。模型输出必须是结构化数据，不能直接写入计划库；先经过本地 `validatePlanDraft`：

- 动作 ID 必须存在且已审核；
- 器械必须匹配；
- 总时长必须在容差内；
- 每组次数、秒数和休息在允许范围；
- 高强度动作数量不能超过强度模板；
- 不能包含用户排除动作；
- 不能出现医疗建议；
- 验证失败时回退到本地规则生成器。

## 11. 自定义计划管理

用户可以：

- 预览；
- 修改名称；
- 调整动作顺序；
- 替换动作；
- 修改组数、次数、秒数和休息；
- 收藏；
- 置顶到计划页；
- 再次训练；
- 复制为新计划；
- 删除。

自定义计划保存在本机，使用版本化 schema。加载时过滤不存在或未审核的动作，并提示用户替换，不能使旧计划导致应用崩溃。

## 12. 数据与模块边界

新增模块建议：

- `exercise-media-manifest.ts`：素材、帧数、审核状态；

- `plan-library.ts`：固定计划；

- `media-audit.ts`：素材清单和自动检查。

现有 `exercises.ts`、`expanded-exercises.ts` 和 `plans.ts` 逐步迁移为读取这些模块，不做一次性重写。

## 13. 测试与验收

### 13.1 动作数据

- 总动作数约 152；
- ID 唯一；
- 中文名唯一或有明确变体说明；
- 四类新增数分别为 35、30、20、15；
- 所有必填字段完整；
- 所有媒体路径存在；
- 未审核媒体不显示为正式素材；
- 实时动作必须有分析器和测试映射。

### 13.2 素材

- 图像尺寸和帧数符合标准；
- 动图能循环；
- 不出现透明或缺失文件；
- 每个正式素材有人工式审核状态；
- 抽查桌面和手机卡片裁切；
- 每帧逐项执行第 6.3 节检查。

自动测试不能证明“没有穿模”，因此素材完成必须同时具备自动清单和视觉审核记录。

### 13.3 实时识别

- 每个 A 级动作有起始、完成、幅度不足、稳定或对齐、追踪丢失测试；
- 快速动作有连续重复测试；
- 交替动作按每侧一次计数；
- 正面和侧面支持与声明一致；
- 语音不重复轰炸，不播报过时阶段。

### 13.4 计划

- 12 套固定计划均可完整运行；
- 目标次数和休息能推动计划状态机；
- 轻、中、高各 4 套；
- 不同目标、器械、时长和历史表现得到不同推荐；
- 本地自定义计划可生成、编辑、收藏、重开和删除；
- 模型输出验证失败时能安全回退。

### 13.5 全应用

- 全量单元测试通过；
- TypeScript 检查和正式构建通过；
- 本地页面无控制台错误；
- 桌面宽度和手机宽度均可使用；
- 现有实时训练、语音、记录、身体数据和计划功能不退化。

## 14. 分批顺序

1. **基础设施批**：拆分动作数据、媒体清单、能力分级、计划校验和测试工具。
2. **第 1 动作批**：25 个徒手和活动度动作，建立角色圣经与关键帧流程。
3. **第 2 动作批**：25 个哑铃动作，重点审核器械穿模。
4. **第 3 动作批**：25 个弹力带与剩余哑铃动作，重点审核锚点和受力方向。
5. **第 4 动作批**：25 个瑜伽、核心和有氧动作，完成约 152 个总数。
6. **计划批**：12 套固定计划与周安排。
7. **个性化批**：推荐器、本地生成器、语音需求解析和收藏管理。
8. **模型接口批**：服务端接口契约、结构化输出和回退测试；暂不配置真实 API Key。
9. **最终验收批**：逐项视觉、桌面、手机、摄像头、测试和构建审计。
