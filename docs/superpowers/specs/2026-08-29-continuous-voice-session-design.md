# 持续语音录入与断线恢复设计

## 目标

身体数据语音录入不设置产品层字数或时长上限。一次录音会话只在用户主动点击“暂停录音”时结束；浏览器静音检测、单段识别结束或短暂网络波动不能强迫用户重新点击开始。

## 用户流程

1. 用户点击“开始录音”，按钮立即变为“暂停录音”。
2. 用户可以自然说话和停顿，识别文字持续追加。
3. 浏览器单段识别自然结束时，应用自动启动下一段，页面仍保持“正在录音”。
4. 网络短暂中断时，页面显示“连接波动，正在自动恢复”，应用按退避间隔自动重连；已识别文字保持不变，用户无需重复点击。
5. 用户点击“暂停录音”后，输入框立即恢复编辑能力。
6. 用户修改文字后点击“继续录音”，新识别内容接在修改后的文字后面。
7. 用户点击“确认并保存”后，解析文字并保存到对应的身体或运动能力数据。

## 文本合并规则

- 不直接把新片段机械拼接到旧文本。
- 比较旧文本结尾与新片段开头的最长相同部分，只追加尚未出现的内容。
- 如果新片段完全包含旧文本末尾，则以更完整的新片段替换重叠部分。
- 暂停后由用户编辑的文字作为下一次续录的唯一基准。
- 不自动改写用户已经编辑的语义；只处理相邻重复片段和空白。

## 识别状态

- `idle`：未录音或已经暂停，可编辑。
- `listening`：识别正常，按钮为“暂停录音”。
- `reconnecting`：连接波动，自动恢复中；按钮仍为“暂停录音”。
- `processing`：用户主动暂停后整理最后一段。
- `error`：权限被拒绝、麦克风缺失等无法自动恢复的问题。
- `unsupported`：浏览器没有语音识别能力，允许直接手动输入。

## 异常策略

- `no-speech`、浏览器自然 `end`：自动续接，不显示错误。
- `network`：保留会话，按 0.6、1.2、2.4、4 秒上限循环重连；收到新识别结果后重置退避。
- 权限拒绝、麦克风缺失、服务未开放：停止会话并解释原因，但保留已有文字并允许手动修改。
- 用户在自动恢复期间点击暂停：立即停止重连并进入可编辑状态。
- 页面关闭或切换生命周期：销毁识别会话，不在后台继续监听。

## 当前能力边界

浏览器语音服务断线期间的声音无法被当前 Web Speech API 补录。当前版本保证“不丢已识别文字、不强迫反复点击、恢复后继续追加”；未来接入流式语音 API 或本地模型后，再保证断线音频缓存和补识别。代码保留统一识别入口，后续不需要重做页面交互。

## 验证

- 长会话经过多次浏览器 `end` 后仍保持录音状态。
- 多次 `no-speech` 不结束会话。
- `network` 错误进入自动恢复，且用户可以随时暂停。
- 续录不会清空已编辑草稿。
- 相邻重复片段只保留一次。
- 不可恢复错误仍保留草稿并允许手动输入。
- 原有计划语音入口继续兼容新增状态。
