# FORM 邀请制、AI 教练与本地数据设计规格

日期：2026-08-31  
状态：待用户最终审阅  
范围：邀请制访问、DeepSeek 后端接入、独立 AI 教练页面、本地数据隔离、备份恢复、删除、错误上报

## 1. 背景与当前事实

FORM 当前是 Vite + TypeScript 的纯前端应用，动作识别在浏览器本机运行。现有身体资料、训练记录、能力记录、偏好和收藏计划分别写入固定名称的 `localStorage` 项；当前没有真正的账户、邀请码后端、账户级数据隔离或 DeepSeek 生产调用。

现有保存能力并不完整：

- 收藏计划可在同一浏览器重新打开，也可取消收藏，但最多 12 套。
- 未收藏的生成结果刷新后消失。
- 训练记录最多 12 条，只提供全部清空，没有单条删除。
- 身体快照支持修改和单条删除。
- 运动能力记录没有删除入口。
- AI 对话尚未实现。
- 固定 `localStorage` 键没有按用户命名；同一浏览器切换账户会产生数据串用风险。
- `localhost` 与正式域名属于不同 Origin，本地数据不能自动互通。

## 2. 产品目标

1. 产品只允许受邀用户进入。
2. DeepSeek API Key 只存在后端环境变量中，不进入网页、构建产物或本地备份。
3. 身体、训练、计划和 AI 对话采用“本地优先”保存，产品后台默认不可见。
4. 同一设备上的不同账户严格隔离；再次登录同一账户可继续使用原有本地数据。
5. 用户可导出加密备份，并在新设备导入恢复。
6. 每一类用户数据均可查看、继续使用、修改或删除。
7. 产品后台仅接收经过清洗的匿名技术报错；详细诊断必须由用户主动授权。
8. AI 的价值体现在计划生成、训练复盘、身体数据解释、语音指标解析和健身问答，而不进入逐帧动作识别链路。

## 3. 非目标

- 不做云端个人健康档案和跨设备自动同步。
- 不把摄像头原始画面、动作视频、骨骼序列或语音原音上传到产品后台。
- 不提供医疗诊断、用药建议或治疗方案。
- 不用大模型替代本地实时动作计数、状态机和安全阈值。
- 不让 AI 自动改写身体关键数据；所有写入必须经过用户确认。

## 4. 已选 UI 与信息架构

### 4.1 底部导航

移动端保持五个入口：

`首页｜动作｜AI 教练｜计划｜我的`

原“记录”和“身体”收进“我的”。功能不删除，只整理信息架构。

### 4.2 AI 教练页面

采用“对话优先”方向，不使用固定男性、女性、机器人或 AI 球形象。专业感由数据依据、具体判断和可执行操作建立。

页面结构：

1. 顶部标题“AI 教练”和“历史”。
2. 上下文条显示本次已读取的本地资料类别，例如“身体数据、最近训练、已存计划”。
3. 对话主区域。
4. AI 回答旁显示简洁“建议依据”栏，明确哪些本地数据支持结论。
5. 回答下提供可执行操作，例如“生成 20 分钟计划”“查看上次训练”“保存到我的计划”。
6. 空对话状态仅保留三个快捷入口：
   - 安排今天训练
   - 分析上次表现
   - 解释身体变化
7. “教我怎么操作”不作为首页快捷入口；用户自然提问时仍能回答，固定指南放入“我的 > 帮助”。
8. 底部提供可持续输入的文字与语音入口。

具体动作教学时才显示统一风格的动作示范图或动图，不设置固定教练人像。

## 5. 邀请码与账户恢复

### 5.1 首次激活

- 管理员生成单用户邀请码，可设置有效期、最大激活次数和 AI 配额。
- 邀请码只用于首次激活；成功后立即失效，避免转发共用。
- 后端创建不可猜测的 `account_id`，设置 `HttpOnly + Secure + SameSite` 会话 Cookie。
- 客户端不得把邀请码当作长期密码保存。

### 5.2 再次登录

- 首次激活后生成只显示一次的账户恢复码。
- 服务端只保存恢复码的安全哈希，不保存明文。
- 用户可正常保持登录；会话过期、换浏览器或清理 Cookie 后使用恢复码重新进入。
- 管理员可以禁用账户、撤销会话、重置恢复码和调整 AI 配额。
- 邀请码/恢复码只恢复访问资格，不恢复本地内容；新设备还需导入加密备份。

### 5.3 管理后台最小范围

后台只包含：

- 邀请码生成、失效、使用状态和配额。
- 账户启用/禁用和恢复码重置。
- 匿名技术错误聚合与诊断编号查询。
- AI 调用次数、失败率和耗时，不展示用户提示词或身体数据。

## 6. 本地数据架构

### 6.1 存储引擎

将分散的 `localStorage` Store 迁移为统一 IndexedDB 数据层。IndexedDB 更适合结构化记录、事务、版本迁移和容量管理。

建议对象仓库：

- `account_meta`
- `body_profiles`
- `body_snapshots`
- `capacity_records`
- `training_sessions`
- `plan_drafts`
- `saved_plans`
- `coach_threads`
- `preferences`
- `local_errors`
- `migration_state`

每个账户使用独立数据库，数据库名称由不可逆的账户散列派生，例如 `form-local-<accountHash>`。应用只允许根据当前有效会话打开对应数据库，不使用一个全局数据库再由界面过滤。

所有记录必须包含：

- `accountId`
- `id`
- `schemaVersion`
- `createdAt`
- `updatedAt`

所有查询必须显式带当前 `accountId`，禁止无账户范围的全表读取。

### 6.2 账户隔离

- 每个账户使用上述独立数据库，不采用可漏筛选条件的共享表方案。
- 每个设备为账户生成独立、不可导出的 Web Crypto 数据密钥，并以 `CryptoKey` 形式保存；敏感值不以明文 JSON 存储。
- 敏感字段使用 Web Crypto AES-GCM 加密后写入 IndexedDB。
- 退出登录时关闭数据库句柄、清除内存中的解密材料并隐藏该账户数据。
- 退出登录不等于删除本地数据。
- “删除此设备上的个人数据”与“删除账户”是两个独立操作。
- 通过 CSP、依赖约束和禁止第三方脚本降低 XSS 读取本地数据的风险。

这里的账户隔离保护的是产品正常使用和误操作场景，不应向用户承诺能抵抗获得同一浏览器配置文件、开发者工具或操作系统控制权的攻击者。真正共用电脑时应建议使用不同的系统/浏览器用户；后续可增加本地解锁 PIN。

## 7. 数据生命周期

| 数据类型 | 保存时机 | 保留规则 | 再次登录 | 删除能力 |
| --- | --- | --- | --- | --- |
| 计划草稿 | 生成成功后自动保存 | 7 天自动清理 | 可继续编辑、收藏或开始 | 单条删除、全部清空 |
| 已收藏计划 | 用户确认收藏 | 直到用户删除 | 可直接调出训练 | 编辑、复制、归档、删除 |
| 训练记录 | 完成或主动结束训练 | 直到用户删除；不再限制 12 条摘要 | 用于趋势、复盘和计划推荐 | 单条、批量、全部删除 |
| 身体快照 | 用户确认输入 | 直到用户删除 | 用于变化趋势和建议依据 | 修改、单条、全部删除 |
| 运动能力记录 | 用户确认输入 | 直到用户删除 | 用于强度和重量推荐 | 修改、单条、全部删除 |
| AI 教练对话 | 每轮回答完成后 | 直到用户删除；可关闭历史 | 可继续原对话 | 改名、单条对话删除、清空全部 |
| 摄像头帧/骨骼序列 | 仅内存分析 | 每帧处理后释放 | 不保留 | 无需删除 |
| 语音原音 | 浏览器识别期间临时使用 | 识别结束即释放 | 不保留 | 无需删除 |
| 识别文字 | 用户确认前为草稿 | 确认后只写入目标记录或本地对话 | 按目标记录展示 | 可修改、删除 |
| 本地技术错误 | 错误发生时 | 最近 50 条 | 通过诊断编号查看 | 清空 |

### 7.1 删除交互

- 每条记录均提供明确删除入口，不只提供“全部清空”。
- 删除后提供短暂撤销窗口；窗口结束后执行本地硬删除。
- 批量删除和删除全部数据需要二次确认，并显示将删除的数据数量。
- 删除 AI 对话不会自动删除已经保存成计划或身体记录的结果；界面需说明关联关系。
- 用户可以关闭 AI 历史；关闭后新对话仅保持到页面/会话结束。

### 7.2 应用升级与动作下架

- 所有记录带 `schemaVersion`，升级时使用可回滚迁移。
- 收藏计划保存稳定动作 ID，而不是依赖显示名称。
- 动作下架或暂不可训练时，旧计划仍可查看；开始前提示替换，不允许直接崩溃或静默删计划。

## 8. 加密备份、导入与迁移

### 8.1 导出

- 用户从“我的 > 数据与隐私 > 导出备份”创建加密备份文件。
- 备份包含账户本地数据、模式版本、校验信息和导出时间，不包含 API Key、邀请码、会话 Cookie或恢复码。
- 用户设置备份密码；使用基于密码派生的密钥和 AES-GCM 加密。
- 密码只由用户持有，平台无法找回。

### 8.2 导入

- 导入前验证文件完整性、版本和密码。
- 先预览计划、记录、身体快照和对话数量。
- 用户选择“合并”或“覆盖”。
- 合并按稳定 ID 去重，冲突时保留更新时间较新的版本，并生成导入报告。
- 导入失败不得破坏现有数据。

### 8.3 localhost 到正式域名

浏览器禁止不同 Origin 直接读取彼此的 IndexedDB/localStorage。因此正式上线前：

1. 当前本地版本提供一次性旧数据导出。
2. 正式域名首次登录时展示“导入原设备数据”。
3. 完成导入并验证数量后，用户自行决定是否清理旧站数据。

不得承诺自动跨域迁移。

## 9. DeepSeek 接入与 AI 编排

### 9.1 后端代理

所有 DeepSeek 请求经 veFaaS 后端代理。环境变量：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL=https://api.deepseek.com`
- `DEEPSEEK_MODEL=deepseek-v4-flash`
- `SESSION_SECRET`
- `INVITE_HASH_PEPPER`
- `ERROR_REPORT_SALT`

模型名称必须可配置，避免模型升级时修改前端。

### 9.2 AI 入口

后端端点建议：

- `POST /api/ai/coach/stream`
- `POST /api/ai/plan`
- `POST /api/ai/session-insight`
- `POST /api/ai/voice-parse`

客户端从本地选择当前任务所需的最小上下文，组成 `ContextEnvelope`。后端只做校验、脱敏、配额、调用和结果验证，不把请求内容写入业务数据库。

### 9.3 意图路由

AI 教练统一识别：

- 计划生成/调整
- 训练复盘和下一次建议
- 身体数据解释
- 语音身体指标解析
- 软件功能引导
- 一般健身问答
- 医疗边界问题
- 与健身完全无关的问题

明显快捷操作优先本地路由；模糊自然语言再让模型输出严格 JSON 意图。模型失败时保留本地规则和原功能。

### 9.4 安全与结果落地

- 计划输出必须通过 JSON Schema、动作白名单、器械匹配、组数/次数/休息范围验证。
- AI 不能创建当前动作库不存在或不可执行的实时纠正动作。
- 语音解析结果先显示可编辑确认页，用户确认后才写入身体/能力记录。
- 训练复盘必须基于实际记录；没有训练数据时不得夸奖“完成得不错”。
- 医疗问题只说明对健身的影响、风险和就医提示，不诊断、不推荐药物。
- 非健身问题使用简短固定边界话术，并引导回产品能力。
- DeepSeek 不参与摄像头逐帧动作识别和即时计数。

### 9.5 本地保存与远程处理的边界

“保存在本地”不等于“从不离开设备”。AI 推理时必要的文字和摘要会被发送给 DeepSeek，但：

- 产品后台不持久保存请求正文。
- 不发送姓名、手机号、邀请码、恢复码等直接标识。
- `user_id` 使用不可逆、轮换的伪匿名值。
- 默认不发送原始照片、视频、语音或完整历史。
- 每次调用界面显示“本次参考了哪些资料”。
- 隐私说明必须向用户明确披露第三方模型处理。
- 首次把身体或健康摘要发送给第三方模型前取得单独、可撤回的明确授权；用户拒绝后仍可使用本地动作识别和固定计划。

## 10. 匿名错误上报

### 10.1 自动上报字段

- `errorCode`
- `errorFingerprint`
- `appVersion`
- `module` / `page`
- 粗粒度浏览器和操作系统类型
- 发生时间
- 响应耗时或阶段
- 匿名安装 ID（可重置，不含账户信息）
- 后端请求追踪 ID（若存在）

设置页提供“发送匿名错误报告”开关和清晰说明；关闭后仅在本地保留最近错误，除非用户主动发送诊断。

禁止自动上报：

- 身高、体重、体脂、疾病和身体快照
- 自由输入、聊天原文和语音文字
- 原始语音、图片、视频和骨骼序列
- 邀请码、恢复码、Cookie、API Key
- 完整 URL 查询参数

### 10.2 详细诊断

- 用户看到清晰的诊断编号。
- 只有用户点击“发送详细诊断”并明确确认后，才上传临时诊断包。
- 上传前显示包含项目，允许取消。
- 诊断包设置短期自动删除和访问审计。

### 10.3 后端保护

- 服务端再次执行字段白名单和脱敏，不信任客户端清洗。
- 错误上报限流、去重，避免循环报错淹没后台。
- 管理后台默认只展示聚合趋势和诊断编号。

## 11. API 与服务器数据

建议认证端点：

- `POST /api/auth/invite/redeem`
- `GET /api/auth/session`
- `POST /api/auth/recover`
- `POST /api/auth/logout`
- `POST /api/auth/revoke-sessions`

建议错误端点：

- `POST /api/errors/anonymous`
- `POST /api/errors/diagnostic`

服务端持久化数据仅限：

- 邀请码哈希和状态
- 账户 ID、状态、AI 配额和恢复码哈希
- 会话/撤销信息
- 匿名错误事件和授权诊断包
- 不含内容的 AI 用量与延迟统计

## 12. 错误、失败与降级

- IndexedDB 不可用：进入只读/临时模式，明确提示不会保存，不假装成功。
- 空间不足：先提示导出与清理，不静默删除用户记录。
- 加密失败：阻止写入并保留当前编辑内容，给出重试。
- DeepSeek 超时/欠费/限流：显示可重试状态；计划与复盘回退本地规则。
- AI 流式中断：保留已显示内容，但标记“回答未完成”，不自动写入数据。
- 邀请码失效：说明原因和获得新邀请码的方式，不进入半登录状态。
- 恢复码失败：限制尝试频率，不暴露账户是否存在。
- 导入失败：保持现有数据库原样，输出错误原因和诊断编号。
- 数据迁移失败：回滚并保留旧数据，禁止部分迁移后继续运行。

## 13. 验证与测试

### 13.1 账户隔离

- 同一浏览器 A 保存计划并退出，B 登录后看不到 A 的任何记录。
- A 再登录同一设备，所有本地记录可恢复。
- 会话过期后恢复码重新登录，仍绑定同一 `accountId`。
- 注销、退出和删除本地数据行为严格区分。

### 13.2 生命周期

- 计划草稿刷新后恢复，7 天后清理。
- 收藏计划可重新打开、开始、修改、复制和删除。
- 训练、身体、能力、对话均支持单条和批量删除。
- 删除关联数据不误删其他已保存结果。
- 动作下架后旧计划显示替换提示。

### 13.3 备份

- 正确密码可导入；错误密码和损坏文件不修改现有数据。
- 合并不重复创建相同记录；覆盖前二次确认。
- 旧版本备份经过迁移后仍可使用。
- 备份文件中不存在 API Key、Cookie、邀请码和恢复码。

### 13.4 隐私与错误上报

- 自动错误请求经快照测试确认无用户文本和身体数据。
- URL、堆栈和请求信息经过服务端二次脱敏。
- 未授权时无法上传详细诊断。
- 管理后台无用户个人记录入口。

### 13.5 AI

- 意图路由覆盖快捷入口、模糊表达、医疗边界和无关问题。
- 模型输出越界动作、异常组数或缺字段时被拒绝并回退。
- 用户未确认前，语音解析不得写入本地身体数据。
- 无训练记录时总结不得生成虚假夸奖。
- DeepSeek 不可用时核心训练和本地动作识别仍可使用。

## 14. 分阶段实施

### 阶段 1：基础安全与数据层

账户命名空间、IndexedDB、旧数据迁移、统一删除和测试。

### 阶段 2：邀请制后端

邀请码、恢复码、Cookie 会话、管理员最小页面和配额。

### 阶段 3：AI 教练

独立页面、意图路由、计划/复盘/语音解析、DeepSeek 后端代理和本地历史。

### 阶段 4：备份与错误中心

加密导入导出、匿名错误上报、用户授权诊断和管理员错误视图。

### 阶段 5：上线前验证

跨账户隔离、隐私扫描、故障降级、正式域名迁移演练和端到端测试。

## 15. 验收标准

- 不同账户在同一设备上无法互相看到本地数据。
- 同一账户再次登录同一设备能恢复所有已保存内容。
- 新设备只有导入加密备份后才能恢复内容。
- 用户能对所有持久化数据进行单条删除或全部清空。
- 管理后台看不到身体、训练、计划、聊天等个人内容。
- 平台能收到匿名错误并通过诊断编号定位技术问题。
- DeepSeek Key 不出现在客户端，模型失败不影响本地训练主链路。
- AI 教练页面采用已确认的对话优先设计，无固定人物形象，快捷入口仅保留三项。
