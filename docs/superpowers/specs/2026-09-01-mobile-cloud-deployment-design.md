# FORM 手机 Web 首版云端部署设计

日期：2026-09-01

## 目标

把当前本地运行的 FORM 健身教练发布为一个通过 HTTPS 访问的手机 Web 产品。用户可在 iPhone Safari、Android Chrome 和电脑浏览器中使用邀请码进入，使用 AI 教练、摄像头动作识别、训练记录和身体状态等现有功能。

首版不做 App Store 安装包，不做电脑与手机之间的自动数据同步。

## 已确认的产品边界

- 每台设备独立保存身体数据、训练记录、计划、能力记录和 AI 对话。
- 用户可以通过加密备份手动迁移数据；导入前不覆盖现有数据。
- 平台不保存用户的身体与训练明细。
- 平台只接收经过裁剪的客户端错误信息，不接收身体、训练或对话正文。
- AI 教练只把当前问题必需的最少上下文临时发送给 DeepSeek。
- 产品只提供健身参考，不做医疗诊断、治疗或用药建议。

## 推荐架构

采用单一 veFaaS Node 应用，而不是纯静态站点或前后端分开部署。

一个 HTTPS 域名同时承载：

1. 构建后的 Vite 前端静态资源。
2. `/api/auth/*` 邀请码与恢复入口。
3. `/api/ai/*` DeepSeek 服务端代理。
4. `/api/errors` 最小化错误上报。

这样可以保持同源 Cookie，避免跨域鉴权问题，也只需要维护一次部署和一个公网地址。

## Node 服务

新增生产 Node HTTP 服务：

- `/api/*` 请求交给现有 FORM API 处理器。
- 其他路径优先返回 `dist` 中的静态资源。
- SPA 未命中路径回退到 `dist/index.html`。
- 监听平台提供的 `PORT`，本地默认端口只用于开发。
- 启动前检查生产环境所需密钥，缺失时输出明确错误并拒绝以不安全默认值启动。

本地开发仍可使用 Vite；生产环境不再使用 Vite 开发中间件。

## 无数据库邀请码与恢复机制

首版不使用云数据库，也不再把邀请码和账户写入实例本地文件。

### 邀请码

- 云端环境变量只保存一个或多个邀请码哈希，不保存邀请码明文。
- 用户输入邀请码后，服务器使用同一 Pepper 计算哈希并进行恒定时间比较。
- 首版邀请码允许重复使用，不追踪使用次数。
- 邀请码泄露时，通过替换云端哈希并重新发布配置完成撤销。

### 会话

- 验证成功后生成随机账户 ID。
- 服务器签发带有效期的 HMAC 会话 Cookie。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`。
- Cookie 不包含身体或训练数据。

### 恢复码

- 恢复码包含账户 ID、有效期和服务器签名，不依赖数据库查询。
- 服务器验证签名和有效期后重新签发登录 Cookie。
- 恢复码不用于恢复设备上的身体或训练数据；这些数据仍需通过加密备份迁移。
- 产品文案必须明确区分“恢复访问”和“恢复本机数据”。

## 数据流与隐私

### 设备本地

以下数据按账户空间保存于 IndexedDB：

- 身体档案与历史变化。
- 训练记录和运动能力记录。
- 收藏或生成的计划。
- AI 对话记录。
- 偏好和设备配置。

### DeepSeek 请求

- API Key 只存在 veFaaS 服务端环境变量中。
- 浏览器永远拿不到 API Key。
- 服务端只发送回答当前问题需要的上下文。
- 请求不在 FORM 服务端落盘。
- 隐私说明需告知用户：相关上下文会由 DeepSeek 处理，但 FORM 不保存该请求正文。

### 错误上报

只允许上传白名单字段：错误类型、错误名称、截断后的错误信息、不含查询参数的页面路径和时间。账户标识经过不可逆摘要处理。

## 云端环境变量

生产环境至少需要：

- `NODE_ENV=production`
- `PORT`：由平台提供或按平台约定配置
- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL=https://api.deepseek.com`
- `DEEPSEEK_MODEL=deepseek-v4-flash`
- `SESSION_SECRET`：不少于 32 个随机字符
- `INVITE_HASH_PEPPER`：不少于 24 个随机字符
- `FORM_INVITE_HASHES`：逗号分隔的邀请码哈希

`FORM_ADMIN_TOKEN` 和文件型 `FORM_AUTH_STATE_PATH` 不属于首版运行依赖。

## 移动端约束

- 摄像头只能在 HTTPS 或本地安全环境中调用。
- 首次进入训练必须由用户主动点击以申请摄像头、麦克风或音频权限。
- iOS 浏览器对自动播放和语音识别有限制；语音播报需在用户交互后启用，文字输入必须始终可用。
- MediaPipe 继续在设备本地运行，不能把实时视频逐帧发送给多模态模型。
- 性能不足时降低推理帧率或画面分辨率，不能降低计数状态机的正确性。

## 发布流程

1. 增加生产 Node 入口和静态资源服务。
2. 将文件型邀请码机制改为无数据库签名方案。
3. 补充生产配置校验和自动化测试。
4. 本地执行构建、API 测试和生产模式启动测试。
5. 让 veFaaS 重新识别为 Node 服务，显式设置构建命令、启动命令和端口。
6. 创建 veFaaS Application 并关联 APIG 网关。
7. 写入生产环境变量，禁止在日志中显示 Secret 值。
8. 部署并获取 HTTPS 公网域名。
9. 电脑浏览器完成全流程冒烟测试。
10. 手机完成邀请、相机、AI、语音、本地持久化和备份导入验收。

## 验收标准

- 公网 HTTPS 地址可从手机网络访问，不依赖开发电脑运行。
- 未通过邀请码时无法进入应用主体。
- 正确邀请码可进入，错误邀请码被拒绝。
- 刷新或重新打开页面后，会话在有效期内保持。
- DeepSeek Key 不出现在浏览器网络响应、前端代码或构建产物中。
- AI 教练返回非固定、与问题和最小上下文相关的答案。
- 摄像头动作识别在至少一台 iPhone 和一台 Android 设备上可启动。
- 用户数据在同一设备重新打开后仍存在，在另一设备不会自动出现。
- 加密备份可以导出并在另一设备导入。
- 删除本机账户数据后不可在该设备恢复，除非用户持有备份。
- 客户端报错可以被服务器记录，但日志不包含身体、训练或对话正文。

## 已知限制与后续升级

- 首版邀请码不是严格的一人一码，不能统计使用次数。
- 恢复码只恢复访问身份，不恢复本机训练数据。
- 不提供跨设备自动同步。
- 不包含应用商店安装包。

后续需要一人一码、邀请码后台管理、跨设备同步或团队运营数据时，再引入持久化数据库和用户授权同步机制；这些能力不阻塞首版手机 Web 上线。
